## Website

The site is static (no build step) and lives in `docs/`.

```bash
cd docs && python3 -m http.server 8000
```

Open `http://localhost:8000`. Pages: `index.html`, `analytics.html`, `radar.html` (risk scoring), `rti.html` (RTI and appeal drafts), `twin/`.

### Tests

```bash
node --test tests/engine.test.cjs
python3 -m unittest tests/test_extract_validate.py
```

The risk-engine tests show the detectors find *planted* patterns in synthetic data. They say nothing about accuracy on real procurement data (see `docs/ADVANCED.md`, section 7).

### Extraction pipeline

`pipeline/extract_tender.py` sends tender PDFs to Claude with a strict JSON schema and re-validates the output locally. Its validator is unit-tested, but the model call has **not been run against the live API** yet. Needs `pip install anthropic` and an API key.

### Data honesty

- `docs/data/organisations.json` is a **real, dated snapshot** of public tender counts from the Maharashtra eProcurement organisation list.
- `docs/data/tenders.sample.json` is **synthetic**, generated by `scripts/generate_sample_data.py`. It demonstrates the indicators and says nothing about real tenders or companies.
- Replace the sample file with verified data in the same schema (set `"synthetic": false`) to make the dashboard real.

### Deploying to GitHub Pages

`.github/workflows/pages.yml` deploys `docs/` on every push to `main`. One-time setup: **Settings → Pages → Build and deployment → Source: GitHub Actions**.
